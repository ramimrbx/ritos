RitOS

Core Spec

RitOS is a modern C++ freestanding operating system targeting the x86 32-bit architecture. Executing in Protected Mode, the system circumvents bios constraints by executing its kernel directly on bare hardware, communicating via a custom interface called the RitOS_API table.

It integrates a linear VGA framebuffer renderer, custom mouse and keyboard drivers, a Virtual File System (VFS), and a modular binary layout loaded dynamically via the custom RBX binary structure.

Mythic Scroll

RitOS is the holy codex that maps the digital cosmos. Forged in the void of bare metal, it contains the sacred rituals of execution, carving order out of raw transistors and creating a divine hierarchy that separates the gods of Kernel Land (Ring 0) from the mortal programs of User Land (Ring 3).

It binds CPU registers, VGA framebuffer beams, and raw files into a single unified pantheon, carrying messages through shortcuts and scripts to project a visual desktop workspace.

Architectural Design & Layers The Pantheon of the Core

The system splits portable logic from hardware-specific ports. This ensures that the primary GUI libraries, system apps, and VFS implementations can compile on any platform (x86, ARM, or embedded) without modifying a single line of application code.

Privilege Separation (Ring 0 & Ring 3)

RitOS preserves the classic hardware security model of the x86 CPU. The kernel executes inside Ring 0 with full access to ports (outb/inb), interrupt tables, and memory page directories. The userland apps and desktop shell reside in Ring 3. Since they are freestanding programs, they communicate with Ring 0 via standard pointers to the RitOS_API table.

Every element of RitOS corresponds to a deity or sacred concept that maintains stability. The digital realm is organized into the Celestial Realm (Ring 0) where the kernel rules, and the Terrestrial Plain (Ring 3) where applications live in constrained isolation, communicating with the heavens through the Sacred Covenant (The API Table).

Heap Memory Manager Simulator Gaea's Garden: Memory allocation Simulator

This simulator runs a Javascript model of the first-fit heap allocator implemented in kernel/core/memory.c. Every allocation is preceded by a block header specifying its magic status (0xA110C8ED for Used, 0xF7EEB10C for Free) and payload size. Freeing a block automatically merges (coalesces) adjacent free blocks to mitigate fragmentation.

Observe Gaea's garden of memory bytes. Summon new segments of life (Used Blocks) by invoking allocations. Dispel segments (Free Blocks) to let memory merge back into Gaea's essence. Hover over used segments to call kfree.

RBX Binary Format & VFS specification The Sealed RBX Vessels & scrolls of VFS

The RBX format is RitOS's proprietary executable layout. The system does not boot or link ELF directly at runtime; instead, a host compilation tool tools/elf2rbx.cpp converts compiled ELFs into RBX binaries.

The file starts with a packed 64-byte header. Below is the structural layout of this header:

Programs are transported across RitOS inside sealed capsules called RBX Vessels. Every vessel is guarded by a 64-byte runic seal specifying execution requirements and carrying the program's unique symbol glyph (an embedded 32x32 icon) so that compositors can paint them on the desktop plain.

user/lib/rit/include/rit/rbx_format.h 
typedef struct rbx_header {
	char     magic[4];      /* "RBX2" */
	uint16_t version;       /* format version (2) */
	uint16_t arch;          /* target CPU architecture: 1=x86, 2=x64, 3=ARM32, 4=ARM64 */
	uint16_t type;          /* execution type: 1=Module, 2=Standalone program */
	uint16_t header_size;   /* size of header (64 bytes) */
	uint32_t flags;         /* reserved for alignment */
	uint32_t load_addr;     /* absolute memory location to place binary */
	uint32_t entry_point;   /* jump address to start execution */
	uint32_t code_size;     /* length in bytes of binary content */
	uint32_t bss_size;      /* size of zeroed segment following binary */
	uint32_t checksum;      /* sum byte value of code segment */
	uint32_t icon_offset;   /* file position of embedded 32x32 ARGB icon */
	uint32_t icon_size;     /* bytes of icon (4096 bytes or 0) */
	char     name[20];      /* NUL-terminated app display name */
} __attribute__((packed)) rbx_header_t;

VFS & Virtual File Shortcuts Hermes' VFS scrolls & Shortcut links

The Virtual File System is loaded directly into RAM at startup via embedded binary structures in the kernel. Individual files have a size limit of 64KB (content[65536]) and the directory hierarchy is flat but supports virtual path separators (like /sys/ or /desktop/).

Shortcuts (.stct files) are simple text files storing the absolute path to their destination binary (e.g., /sys/calculator.rbx). The desktop window explorer maps these paths to render the shortcut icons dynamically by loading the target RBX's embedded icon, separating visual shortcuts from actual program resources.

VFS represents the scrolls of Hermes, storing files in RAM caches of up to 64 kilobytes. Rather than copying programs across the screen, the desktop uses Shortcut links (.stct). These links act as portal points: when opened, they direct Hermes to fetch the target vessel from the /sys vaults, extracting its icon automatically.

Building & Executing the System The Rites of Summoning

To compile the kernel and build a bootable ISO, you must install the x86 cross-compiler tools. Run the commands below in your host Linux (Ubuntu/Debian) terminal.

To summon the RitOS world, you must compile the runic equations using the tools of the host environment. Execute the commands below to compile and boot the ISO within the virtual mirror (QEMU).

1. Install Host Dependencies

Host Terminal 
sudo apt update && sudo apt install -y \
    build-essential \
    gcc-multilib \
    g++-multilib \
    grub-pc-bin \
    xorriso \
    mtools \
    qemu-system-x86

2. Compile using Make or Script

The build script clears previous builds, links fonts and assets, packages applications into RBX format, and creates a GRUB boot ISO at build/ritos.iso.

The assembly script prepares the environment, compiles source text into executable runic codes, packages them, and shapes the bootable vessel at build/ritos.iso.

Build Compilation 
# Method A: Build script (Recommended)
./scripts/build_iso.sh

# Method B: Makefile
make clean && make

3. Run the Virtual Machine emulator

Execution in Emulator 
# Run compiled ISO with QEMU x86 emulation
qemu-system-i386 -cdrom build/ritos.iso
